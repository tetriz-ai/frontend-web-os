# Reading list: the fwos sample app

This is the sample app for Frontend Web OS (fwos). It exists to test and demonstrate the plugin,
so everything in it was made by following the fwos steps in order, with the `fwos` CLI as the
source of truth:

1. `fwos init`, then discovery: [the brief](docs/app/brief.md), approved.
2. Research: skipped, with the reason logged.
3. Architecture: [modules.json](docs/app/modules.json) and the [API contract](packages/api-contract/openapi.yaml) with its fixtures.
4. Design system: the neutral starter, built into tokens.
5. Screens: the scaffold, then the list page in every state on fake data, and [ia.json](docs/app/ia.json).
6. Spec and test plan: [spec.md](docs/app/spec.md) (10 first-release acceptance criteria and 1 later one) and [test-plan.md](docs/app/test-plan.md), approved together.
7. Build in three slices. For each one the tests came first, failed, and were locked by hash before any feature code was written.
8. Acceptance: the full suite, then [the acceptance report](docs/app/reports/acceptance.md), which says Done.

Every choice made along the way is a row in [decisions.md](docs/app/decisions.md).

The app is a personal reading list saved on one device. You save a link (a web address and an
optional title), mark links read or unread, filter the list to All, Unread or Read (kept in the
address, like `/?show=unread`), and delete with a few seconds to undo. There's no account or backend
storage: links are saved in this browser, behind a repository that implements the same API
contract a real backend would.

An already-open tab can use its local data without a connection. The app does not cache its
shell for offline opening, reloading or navigation. The approved brief's broader offline wording
is historical intent; the acceptance report does not prove offline launch or reload. Those
approved records are preserved as they were.

## Run it

Use Node 22.22.2 or later in the 22.x line, Node 24.15.0 or later in the 24.x line, or Node 26 or
newer, plus pnpm. These are the supported ranges of the pinned test dependencies. From this folder:

```bash
pnpm install        # also links the fwos CLI from this repo (fwos-check: link:../..)
pnpm dev            # http://localhost:3000
```

While `pnpm dev` runs, `http://localhost:3000/fwos-screens` shows the list page in each of its
states (loading, empty, filtered-empty, error, ready) on the contract's fixtures.

## Check it

```bash
pnpm typecheck      # TypeScript
pnpm exec fwos tests run  # records Vitest + production Playwright evidence on port 3210
pnpm check          # fwos check: PASS, FAIL or OFF for every check, with the reason
```

`pnpm e2e` needs Chromium for Playwright. If it isn't installed yet:
`pnpm --filter web exec playwright install chromium`.

Test results land in `.fwos/local/results/`. Use `pnpm exec fwos tests run` before `pnpm check`
to record the current inputs and exact result bytes; direct runner output alone does not count at acceptance. This change is accepted, so with no results the traceability check fails, because
no requirement is proven. `pnpm e2e` also runs fwos's harness (`apps/web/e2e/fwos-*.spec.ts`),
which renders each state and opens the app as its one role, and `pnpm check` needs a run of it
since the code last changed.

## What each folder shows

| Folder | What it shows |
|---|---|
| `docs/app/` | The brief, spec, test plan, decisions, `ia.json` (pages and states) and `modules.json` (module walls) |
| `docs/app/reports/` | The acceptance report, generated by `fwos report` from the evidence; never edited by hand |
| `design-system/` | The neutral starter design system: tokens, the component registry and its required states |
| `packages/tokens/generated/` | CSS variables and the Tailwind theme, generated from `design-system/` by `fwos tokens build` |
| `packages/api-contract/` | `openapi.yaml` (listItems, createItem, updateItem, deleteItem), the shared fixtures, and the generated mock fetch |
| `apps/web/app/` | Next.js routes. `page.tsx` is thin: it hands the filter to the feature. `(fwos-screens)/` is the dev-only screens route |
| `apps/web/src/features/reading-list/` | The one feature module: `model/` (rules), `data/` (the local repository and queries), `components/` (the view), and its tests, tagged with the ACs they prove |
| `apps/web/src/screens/` | The list page on fake data, drawn by the feature's own view, and a fixture per required component state |
| `apps/web/src/shared/` | Registered components (`ui/`), the one date and number formatter (`lib/`), the nav and the query provider |
| `apps/web/e2e/` | End-to-end tests, the default rows every fwos app gets (crawl, accessibility, keyboard, themes, phone, production build), and fwos's harness |
| `.fwos/` | fwos state: the change, its approvals (content hashes), locked tests, and one manifest per slice in `slices/` |
